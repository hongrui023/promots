# 批量导入：把一大段文本拆成一条条指令

手里往往已经有一堆现成的指令集合——从别的工具导出的、聊天记录里攒的、
某份技术手册里整整一节的模板。逐条复制粘贴进本应用是纯体力活。

批量导入就是干这个的：**粘贴一大段文本，自动拆成一条条可入库的指令，
逐条确认后一次性导入。**

入口：左侧栏「批量导入」，或桌面端菜单「文件 → 批量导入」。

---

## 一、两套引擎，默认只跑本地那套

| | 规则引擎（默认） | AI 辅助（可选） |
|---|---|---|
| 联网 | 不需要 | 需要 |
| 文本去向 | 只在本机 | 分块后发送到你配置的模型服务 |
| 处理方式 | 识别标题、编号、分隔线来切块 | 先切块，再让模型判断哪块是真指令并起标题 |
| 正文 | 原文 | **原文**（模型拿不到正文的写权限） |
| 成本 | 零 | 每次几厘到几分钱 |
| 适用 | 结构清晰的文档 | 结构松散、规则切不准的长文 |

**默认不勾选 AI**。规则引擎能处理的就不该把文本发出去。

---

## 二、它认识哪些结构

### 分隔线

```
--------------------------------------------------------------------------------
```

一行里全是 `-` `=` `─` `═` `—` `*` 等符号且长度 ≥ 6，视为结构分隔。

代码围栏 ```` ``` ```` 内部的分隔线不算——这点很重要，
粘贴代码片段时不会因为注释里的横线被切开。

### 标题

| 形式 | 例子 | 说明 |
|---|---|---|
| 方括号编号 | `【3.1】读论文：中英对照全文` | 最可靠 |
| Markdown | `## 安装` `### 2.1 配置` | |
| 实心方块 | `■ 3  单技能指令模板` | 无小数点的编号视为章节，不当条目 |
| 纯编号 | `3.2 精读一篇论文` | 必须带小数点，否则会误判「1. 每个模板都能…」 |
| 中文序号 | `一、总则` | 整行要短 |

### 元数据行

```
技能：nature-reader
需要你替换：【论文路径/DOI】【输出目录】
需要产出：paper.md、source_map.json
听众背景：材料方向研究生
```

这些东西会被识别成标签、占位符、备注，**并从正文里摘掉**——
正文保持成「可以直接粘贴走」的样子。

### 占位符

`【论文路径】` 这类会被提取成「待填字段」列在备注里。
`【3.1】`、`【12】` 这种纯编号不算，那是章节序号。

### 粘贴标记

`@long-text:`、`@paste:` 之类的开头标记会被自动剥掉。

## 三、切出来之后，怎么判断哪些是「真指令」

判定错了的代价是不对称的：

- 把说明文字塞进库里 → 库变脏，用户要一条条删
- 把真指令误判成说明 → 用户取消勾选一下就行

所以规则引擎**偏保守：宁可漏勾，不要误勾**。

给出勾选的条目要么点名了技能、要么带占位符、要么有明确的动作词和产物要求。
不好判定的会照样列出来但不勾选，并**写出理由**：

```
未选中：标题像说明性章节；正文过短
未选中：无动作词、无占位符
未选中：对照式内容占 100%
```

点任意一行右侧的箭头可以展开，直接改标题、正文、备注、分类、标签。

快捷操作：

- **只选指令** —— 恢复到「只勾选判定为指令的」（默认状态）
- **全选可用** —— 除了重复项，全勾上
- **全不选**

## 四、去重

导入前会跟库里的已有指令比对，分三档：

| 档 | 判据 | 处理 |
|---|---|---|
| `exact` | 正文归一化后的 MD5 指纹相同 | 标为重复，**禁止勾选** |
| `title` | 标题完全相同 | 同上 |
| `high` | 正文二元组相似度 > 0.86 | 同上 |

候选内部也会互相比对——同一段文本里出现两遍的内容只保留一条。

重复项会显示「与『xxx』重复」，鼠标移上去能看到是跟哪一条撞了。

## 五、AI 辅助是怎么工作的（以及为什么长这样）

值得记一笔，因为前两版都失败了。

**第一版：让模型自己从整段文本里找边界。**

实测不成立。把 7387 字的文本丢给 glm-4-flash，它只吐了一条，
还偏偏是「使用说明」那一节。`finish_reason` 是 `stop`——
模型把整段当成「一段要处理的文本」，处理完开头就宣告完成。

**第二版：规则先切块，模型逐块判断，但要求它把正文原样回吐。**

还是失败。块有 3500 字，模型就要输出 3500 字的 `content`，
加上 JSON 转义直接顶到 `max_tokens`，返回被截断、`JSON.parse` 失败，
**整批结果静默消失**。测试里表现为一半条目凭空不见——最难查的那种 bug。

**第三版（当前）：规则管切块和正文，模型只管判断和起名。**

模型只回答「这块是不是指令」「叫什么名字」「打什么标签」，
几十个 token 就够了。好处是三重的：

1. 输出永远不会顶到上限，不会截断
2. token 消耗降到约 1/10
3. **正文物理上不可能被模型改写**——它根本拿不到写正文的权限

另外 prompt 里必须写清代价不对称：

> 把一条真指令判成 false → 用户永远看不到它，等于内容凭空丢失
> 把说明文字判成 true → 用户取消一下勾选就行
> 所以默认倾向是 keep=true

不写这句，模型会倾向于一律判 false——实测 16 个块全判 false，
一个都不剩。

**兜底**：模型没表态的块，退回规则判断结果并标注出来。
单批失败不影响其他批；但**全部批次都失败会直接报错**，
因为那说明是 Key、网络或额度的问题，静默返回空结果会让用户
误以为「这段文本里没有指令」。

### 支持的模型

「设置 → AI 增强」里选服务商。推荐智谱 GLM，因为：

- 有免费额度，`glm-4-flash` 够用
- **接口返回完整的 CORS 头，网页端可以直接调用**
  （相比之下微云和百度网盘的接口都拿不到跨域头，只有桌面端能用）
- OpenAI 兼容格式，换别家也是改个 Base URL 的事

## 六、实测数据

用一份 7387 字符的技术手册片段（含 6 个章节、20 条编号模板、1 张速查表）：

| | 规则引擎 | AI 辅助 |
|---|---|---|
| 切出候选 | 15 条 | 9 条 |
| 其中真指令 | 9 条（需人工确认） | 9 条（直接可用） |
| 说明性内容 | 6 条（不勾选，需人工忽略） | 0 条 |
| 正文是否被改写 | 否 | 否 |
| API 调用 | 0 | 2 次 |
| 耗时 | < 1 秒 | 约 12 秒 |

AI 辅助的价值在于**省掉人工筛选那一步**——
规则引擎会把速查表、占位符一览、运行环境说明全都列出来让你判断；
AI 直接告诉你哪些不用管。

## 七、自检

```bash
# 规则引擎：76 项断言，用真实结构的文档做夹具
node tools/test-importer.mjs

# AI 路径：真实调用模型，20 项断言
GLM_KEY=你的key node tools/test-ai-import.mjs
```

AI 测试会真的消耗 token（约 2 万），所以**不放进常规自检**，
需要时手动跑。Key 只从环境变量读，不会写入任何文件。
