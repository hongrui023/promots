# 搜索引擎设计

四种模式不是"四种强度"，而是**四类不同的检索意图**。理解这个区别，才知道什么时候该切哪个模式。

---

## 为什么需要四种

一个真实场景：你记得自己写过一段审查代码的指令。

- 记得标题 → 用**快速**，输入 `代码`，立刻出来。
- 记成"代码申查"了 → 快速搜不到，用**模糊**。
- 只记得意思是"帮我看看这段代码有什么问题" → 用**近义词**，搜 `检查` 也能找到标着"审查"的那条。
- 什么都记不清，只知道"我收藏过、跟代码有关的" → 用**自然语言**。

用错模式的体验是"这软件怎么搜不到"，而不是"我搜法不对"。所以还有一个**智能模式**负责替你判断。

---

## 一、快速搜索

**语义**：所有查询词都必须命中（AND）。

**打分表**（越高越优先）：

| 命中位置 | 分值 |
|---|---|
| 标题完全相等 | 120 |
| 标题开头 | 95 |
| 标题包含 | 78 |
| 标签完全相等 | 88 |
| 标签开头 | 70 |
| 标签包含 | 55 |
| 备注包含 | 34 |
| 正文包含 | 20 |
| 拼音首字母匹配标题开头 | 92 |
| 拼音首字母匹配标题任意位置 | 62 |
| 标签拼音匹配 | 58 |
| 多音字变体命中 | 50 |

多词查询时，分数为各词最佳命中之**和**；任一词完全未命中则整条淘汰——这是快速搜索保持精确性的关键。

**热度修正**：最终分乘以 `(1 + ln(1 + 使用次数) × 0.08) × 最近使用加成`。用得多的、刚用过的略微上浮，但不至于让一条高频低相关的结果压过精确命中。

**降级**：如果一条都没命中，自动用模糊算法重试一遍。用户看到的结果是"找到了"，而不是"无结果"，`meta.mode` 会记成 `quick→fuzzy` 并显示在界面上。

## 二、模糊搜索

**语义**：允许部分词命中（覆盖率过半即可）。

### 相似度算法

两个信号加权融合：

```
相似度 = bias × 编辑距离相似度 + (1 - bias) × 二元组 Dice 系数
```

- **编辑距离相似度** = `1 - 距离 / 较长串长度`，带早停（差值超过 `长度 × 0.45` 直接判 0）
- **二元组 Dice 系数** = `2 × |A∩B| / (|A| + |B|)`

**bias 为什么不是固定值**：中文词短（「周报」两个字），二元组只有 1 个，信息量太低，此时编辑距离更可靠，`bias = 0.72`；英文词长、字母可随意替换，Dice 更稳，`bias = 0.45`。

### 滑动窗口

查询 4 个字、标题 11 个字时，整体比对会被长尾稀释到接近 0：

```
「代码申查」 vs 「代码审查codereview」
整体编辑距离 = 8  →  相似度 0.09   ❌
窗口「代码审查」编辑距离 = 1  →  相似度 0.63   ✅
```

所以对长度大于查询的目标串，会滑一个长度等于查询的窗口取最优。这是中文短查询能容错的关键。

### 汉字二元组命中

中文自然语言里，有意义的片段常被无意义的字包住（「跟代码」= 跟 + 代码）。所以当查询长度 ≥ 3 且含汉字时，会检查它的**每个二字片段**是否出现在目标串中，命中即给 0.7 分。

### 拼音维度

查询的拼音首字母与标题首字母串比对：前缀命中 0.92，包含命中 0.7。所以 `xhs` 能找到「小红书…」，`gwxz` 能找到「公文写作…」。

### 阈值与覆盖率

- 单词相似度 ≥ 0.5 记为命中，≥ 0.3 记为弱命中（计 60% 分）
- 命中词数必须 ≥ `ceil(总词数 × 0.5)`

## 三、近义词搜索

**语义**：把每个查询词扩展成同义组，任一成员命中即算命中。

词库是**定向构建**的，不是通用同义词表：`app/js/synonyms.js` 里有 136 组，全部围绕 AI 指令场景。

```
['总结','摘要','概括','提炼','归纳','小结','summarize','summary','abstract']
['翻译','译','转译','translate','translation']
['润色','优化','改写','修饰','打磨','polish','revise','refine']
```

组内**中英混排**，因此 `summarize` 能搜到中文标题的「会议纪要提炼」。

**命中衰减**：直接命中按 100% 计分，通过同义词命中按 86% 计分。这样原词精确匹配仍然排在前面——否则搜「摘要」时，一堆只写了「总结」的结果会把真正标着「摘要」的那条挤下去。

**兜底**：近义扩展可能把原词命中也稀释掉，所以近义模式下一旦没结果，会用快速搜索再兜一层。

## 四、自然语言搜索

两类解析，先用规则，有条件再叠加大模型。

### 规则解析（零配置可用，始终执行）

**槽位填充**：

| 槽位 | 识别什么 | 例子 |
|---|---|---|
| `days` | 时间范围 | 「最近」→ 7 天，「上周」→ 14 天，「本月」→ 31 天 |
| `favoriteOnly` | 是否只看收藏 | 「收藏的」「星标的」 |
| `platforms` | 目标平台 | 「豆包」「ChatGPT」 |
| `sort` | 排序意图 | 「最常用的」→ 按使用次数 |
| `category` | 内容分类 | 把剩余句子丢进分类器判定 |
| `keywords` | 真正的检索词 | 剔除功能性片段后分词 |

**两个关键处理，缺一个就搜不出东西**：

1. **剔除功能性片段**。`最近写的关于数据分析的` 若不处理，会得到 `['最近写','数据分析']` 两个词——而「最近写」在任何指令里都不可能存在。所以先用 `NL_FILLER` 正则剥掉「最近/关于/帮我/有没有/收藏」这类只表达"怎么找"而不含检索信息的词，再分词。

2. **容器词过滤**。「指令」「提示词」「模板」在"我收藏的指令"这种句子里只是被描述的对象，不是检索内容，放进关键词只会污染结果。

**打分语义用覆盖率而非 AND**：自然语言查询分词后必然带碎片，要求全部命中等于永远搜不到。所以改为「至少一个词命中即保留」，相关度完全交给分数和覆盖率加成排序：

```
最终分 = 各词得分之和 × (0.7 + 0.3 × 覆盖率) × 热度
```

每个词依次尝试：**直接命中 → 近义扩展 → 模糊近似**。

### LLM 增强（可选）

配置 API Key 后，当查询长度 ≥ 6 且形似句子（含「的/那些/有没有/帮我/最近」等标记）时，会额外调用大模型把查询解析成结构化条件，与规则结果**合并**而非替换。

随后对候选结果做**语义重排**：把前 40 条交给模型打分，最终分变为 `原分 × 0.4 + 语义相关度 × 180`。

没配 Key 时这一层直接跳过，规则结果照常返回，并在界面上提示"已使用本地规则解析"。

## 五、智能模式：怎么判断该用哪个

```
纯英文字母数字串，长度 ≥ 3        → 模糊
   （用户大概率在打拼音首字母：gwxz、xhs）

含「的/那些/有没有/帮我/最近/收藏过」等标记   → 自然语言
且长度 ≥ 7（命中 2 个标记，或 1 个标记 + 长度 ≥ 10）

查询含近义词组内的词，且长度 ≥ 4   → 近义词

其他                              → 快速
```

判断结果会显示在结果栏（如「智能判定 → nl」），你能看到它选了什么，也能随时手动切。

## 六、拼音层

`app/js/pinyin-data.js` 由 `tools/gen-pinyin.js` 预生成，**零运行时依赖**：

- 覆盖 U+4E00–U+9FFF 共 **20992 个汉字**的首字母
- **1953 个多音字**的全部读法，如「重」→ `cz`，所以「重写」既能用 `zx` 也能用 `cx` 搜到
- 生成物 31 KB，比任何运行时拼音库都小
- 非汉字原样保留，所以中英混合输入（`数据分析SQL` → `sjfxsql`）也能工作

**限制**：只支持首字母，不支持全拼。`xhs` 能搜到小红书，`xiaohongshu` 不行。要做全拼需要完整拼音表（约 100 KB+），对个人指令库来说性价比不高。

---

## 七、性能

索引在**首次查询时构建**，按条目数组引用缓存（`WeakMap`）。索引项包含：归一化后的标题/备注/正文/标签、标题拼音首字母、标签拼音、多音字变体、CJK 字符集。

归一化会去掉全部标点和空白，所以「代码审查（Code Review）」和「代码审查code review」在检索时是同一个串。

实测：14 条数据下快速搜索 **0.1–0.3 ms**。算法本身是 O(条目数 × 词数)，几千条规模下仍在毫秒级。模糊模式因为要做窗口滑动，是唯一有二次开销的模式，但仍在可接受范围。

如果条目数上万，把 `buildIndex` 换成持久化倒排索引即可，接口不用改。

```bash
node tools/verify.mjs
```

搜索相关的断言覆盖：

- 快速：普通词命中、拼音首字母命中
- 模糊：中文错字（周抱→周报）、错字+长标题（申查→审查）、拼音首字母（xhs）
- 近义词：中文扩展（摘要→提炼）、英文扩展（summarize）、单字查询（译）
- 自然语言：纯条件检索（我收藏的）、条件+关键词（我收藏的代码类）、时间槽位、分类槽位、碎片容错（跟代码有关的）
- 智能模式：三种分流路径各自的判定结果
- 过滤器、排序、边界（无结果不抛异常）、耗时、高亮区间定位
